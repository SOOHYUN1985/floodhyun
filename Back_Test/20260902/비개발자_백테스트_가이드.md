# BUJA 전략 백테스트 비개발자 가이드

이 문서는 코드를 수정하지 않고 `One_Day_Minervini_Mark_V1` 전략을 실행하고 결과를 비교하기 위한 안내서입니다.

> 백테스트 결과는 과거 데이터의 모의 결과입니다. 미래 수익을 보장하지 않으며, 이 프로젝트의 `수익률합계`는 실제 계좌의 복리수익률과 다릅니다.

---

## 1. 가장 먼저 알아둘 파일

| 파일 | 용도 | 권장 사용 시점 |
|---|---|---|
| `Main.py` | 백테스트 실행 프로그램 | 직접 수정하지 않음 |
| `smoke_test.json` | 1개 조합 실행 점검 | 처음 실행하거나 환경을 확인할 때 |
| `overnight_test.json` | 중요 이동평균선을 포함한 대규모 테스트 | 1개 조합이 성공한 뒤 |
| `backtest_config.json` | 인자 없이 실행할 때 사용하는 기존 설정 | 기존 결과 재현용 |
| `util.py` | 슬리피지 등 공통 설정 | 비용 가정을 바꿀 때만 |
| `strategy/One_Day_Minervini_Mark_V1.py` | 실제 매수·매도 규칙 | 개발자 검토 없이 수정하지 않음 |
| `result_list.txt` | 실행별 전략 순위가 아래쪽에 계속 추가됨 | 결과의 빠른 비교 |

현재 권장 순서는 `smoke_test.json`으로 동작을 확인한 다음 `overnight_test.json`을 실행하는 것입니다.

## 4. `strategies` 읽는 방법

형식은 다음과 같습니다.

```json
[신고가 탐색기간, [매도 EMA 기간들]]
```

### 예시 1: `[120, [50]]`

- 최근 120일 고가를 돌파하는 종목을 탐색합니다.
- 매수 후 수익 중일 때 종가가 EMA 50일선 아래로 내려가면 전량 매도합니다.

### 예시 2: `[120, [50, 200]]`

- 최근 120일 신고가 조건으로 매수합니다.
- 수익 중 EMA 50일선을 이탈하면 보유수량의 절반을 매도합니다.
- 이후 EMA 200일선을 이탈하면 나머지를 매도합니다.

두 이동평균선을 같은 날 모두 이탈하면 같은 날 전량 매도될 수 있습니다.

### 예시 3: `[240, [10, 20, 50, 200]]`

- 최근 240일 신고가 조건을 사용합니다.
- 수량을 네 부분으로 나누어 EMA 10, 20, 50, 200 이탈 시 차례로 매도합니다.

현재 테스트하는 EMA는 다음과 같습니다.

```text
10, 20, 33, 50, 60, 100, 120, 200, 240
```

50일선과 200일선은 단독 전략과 조합 전략에 반복해서 포함되어 있습니다.

> EMA 매도는 현재 가격이 매수가보다 높은 경우에만 작동합니다. 손실 상태에서는 EMA가 아니라 손절 조건이나 다른 전량매도 조건이 적용됩니다.

## 5. `profit_loss_ratios` 쉽게 이해하기

형식은 다음과 같습니다.

```json
[1R의 가격 간격(%), 절반 익절 R배수]
```

첫 번째 값은 최초 손절 폭이면서 추적 손절선이 올라가는 간격입니다. 두 번째 값은 보유수량 절반을 익절하는 목표 배수입니다.

### `[7, 4]`, 매수가 100원 예시

| 종가 | 수익 상태 | 손절선 또는 동작 |
|---:|---:|---|
| 100원 | 0% | 최초 손절선 약 93원 |
| 107원 | +1R | 손절선을 100원으로 올림 |
| 114원 | +2R | 손절선을 107원으로 올림 |
| 121원 | +3R | 손절선을 114원으로 올림 |
| 128원 | +4R | 절반 익절, 손절선을 121원으로 올림 |
| 이후 121원 미만 | 하락 | 남은 수량 전량매도 |

실제 매도 가격에는 매도 슬리피지 0.5%가 반영됩니다. 가격이 손절선을 건너뛰어 급락하면 손절선 가격이 아니라 그날 계산된 매도 가격에 체결됩니다.

### `[10, 4]`, 매수가 100원 예시

- 최초 손절선: 약 90원
- +10%인 110원 도달: 손절선 100원
- +20%인 120원 도달: 손절선 110원
- +30%인 130원 도달: 손절선 120원
- +40%인 140원 도달: 절반 익절

### `4R`과 `99R`의 차이

현재 `overnight_test.json`에는 두 종류가 들어 있습니다.

- `[7, 4]`: +28%에서 절반 익절
- `[7, 99]`: +693%에서 절반 익절
- `[10, 4]`: +40%에서 절반 익절
- `[10, 99]`: +990%에서 절반 익절

`99R`은 대부분의 종목에서 목표에 도달하지 않으므로 사실상 **중간 절반 익절을 하지 않고 EMA와 추적 손절로 보유하는 비교군**입니다.

첫 번째 값이 30이면 최초 손절 폭도 약 30%가 됩니다. 큰 손실을 허용하는 공격적인 설정이므로 결과가 좋더라도 실전 적용 전에 7%, 10%, 15% 결과와 안정성을 비교해야 합니다.

## 6. 설정 파일을 수정하는 방법

JSON에서는 다음 규칙을 지켜야 합니다.

1. 숫자와 대괄호 구조를 유지합니다.
2. 각 줄 사이에는 쉼표를 넣습니다.
3. 마지막 항목 뒤에는 쉼표를 넣지 않습니다.
4. `// 설명` 같은 주석을 적지 않습니다.
5. 파일을 UTF-8로 저장합니다.

### 전략 하나 추가하기

예를 들어 200일 신고가와 EMA 50/200 매도를 추가하려면 `strategies` 안에 다음 항목을 넣습니다.

```json
[200, [50, 200]]
```

### 위험 설정 하나 추가하기

예를 들어 12% 간격과 4R 절반 익절을 추가하려면 다음 항목을 넣습니다.

```json
[12, 4]
```

전체 조합 수는 다음과 같습니다.

$$
\text{전체 조합 수} = \text{strategies 개수} \times \text{profit\_loss\_ratios 개수}
$$

전략 49개와 위험 설정 11개라면 종목당 539개가 실행됩니다. 숫자 하나를 추가해도 실행 시간이 크게 늘어날 수 있습니다.

### 중복과 잘못된 값

프로그램은 다음 항목을 자동으로 정리하거나 거부합니다.

- 완전히 같은 전략과 위험 설정: 중복 제거
- `[50, 20, 50]`: `[20, 50]`으로 정렬 및 중복 제거
- 신고가 기간 60일 미만: 실행 전 오류
- EMA가 비어 있거나 2일 미만: 실행 전 오류
- 손절 폭 또는 R배수가 0 이하: 실행 전 오류

## 7. 결과 파일 찾기

실행을 시작하면 프로젝트 안에 다음 형식의 폴더가 만들어집니다.

```text
result_연도-월-일_시-분-초
```

예:

```text
result_2026-08-10_22-30-00
```

### 폴더 안의 통합 Excel

```text
result_2026-08-10_22-30-00.xlsx
```

- 전략과 위험 설정별로 Excel 시트가 생성됩니다.
- 각 행은 종목별 결과입니다.
- 시트 아래쪽 `total_return_sum`은 종목별 수익률의 단순 합계입니다.

### 전략별 TXT와 Excel

전략 이름은 다음처럼 표시됩니다.

```text
singo_120_medo_50_200_[7, 4]
```

뜻은 다음과 같습니다.

- `singo_120`: 120일 신고가
- `medo_50_200`: EMA 50/200 분할매도
- `[7, 4]`: 7% 간격, 4R 절반 익절

전략별 Excel에는 다음과 같은 시트가 생성될 수 있습니다.

- `Stocks_Trading_History`: 개별 매매 기록
- `Summary`: 월별 매매 요약
- `Yearly Summary`: 연도별 요약
- `Total Summary`: 전체 요약
- `Duplicated_Date`: 종목 보유기간 중복 현황
- `Monthly_Unique_Stocks`: 월별 보유 종목 수

### `result_list.txt`

모든 실행 결과가 파일 아래쪽에 계속 추가됩니다. 가장 최근 실행 결과는 파일의 가장 아래에 있습니다. 과거 결과와 섞이지 않도록 실행 시작시간 또는 결과 폴더 이름을 함께 기록하는 것이 좋습니다.

## 8. 결과표 읽는 방법

| 항목 | 의미 | 주의점 |
|---|---|---|
| 매매횟수 | 완료된 매매 수 | 너무 적으면 우연일 가능성이 큼 |
| 수익횟수 | 수익으로 끝난 거래 수 | 단독으로 판단하지 않음 |
| 손실횟수 | 손실로 끝난 거래 수 | 손실 크기도 함께 확인 |
| 승률 | 수익 거래 비율 | 승률이 높아도 큰 손실이 있으면 나쁠 수 있음 |
| 수익합계 | 개별 거래 수익률의 합 | 실제 계좌 복리수익률이 아님 |
| 기대값 | 거래당 평균 수익률 | 매매횟수와 연도별 안정성을 함께 확인 |
| TPI | 승률과 평균수익을 결합한 비교 지표 | 프로젝트 내부 상대 비교용 |
| 켈리값 | 승률과 기대값 기반 계산값 | 실제 투자 비중으로 바로 사용하지 않음 |

### 좋은 전략을 고르는 최소 기준

수익합계 1등만 선택하지 말고 다음을 함께 봅니다.

1. 매매횟수가 충분한가
2. 여러 연도에서 고르게 수익이 났는가
3. 특정 한두 종목이 결과 대부분을 만들지 않았는가
4. 손절 폭을 7%, 10%, 15%로 바꿔도 결과가 급격히 무너지지 않는가
5. 신고가 기간 120, 240, 400에서 비슷한 방향이 나타나는가
6. 4R과 99R 중 어느 한쪽에서만 과도하게 좋은 결과가 나오지 않는가
7. EMA 50/200 조합이 인접한 표준 EMA 조합보다 일관적인가

인접한 여러 설정에서 결과가 비슷해야 과최적화 가능성이 낮습니다.

## 9. 반드시 알아야 할 결과의 한계

### 실제 포트폴리오 수익률이 아님

각 종목은 독립적으로 1억 원을 보유한 것처럼 계산됩니다. 동시에 여러 종목을 매수할 때의 전체 자금 한도는 적용하지 않습니다. 따라서 모든 종목의 수익률을 더한 `수익합계`를 실제 계좌 수익률로 해석하면 안 됩니다.

### 비용이 완전하지 않음

- 매수 슬리피지 0.5% 반영
- 매도 슬리피지 0.5% 반영
- 증권사 수수료 별도 차감 없음
- 거래세 별도 차감 없음

### 일봉 백테스트의 한계

하루 중 정확한 체결 순서를 알 수 없습니다. 급등락, 갭 하락, 거래정지에서는 실전 체결 가격과 차이가 커질 수 있습니다.

### 데이터 품질 의존

결과 종료일은 데이터베이스의 마지막 날짜에 달려 있습니다. 데이터가 오래되었거나 누락되면 최신 시장을 반영하지 못합니다.

## 10. 실행을 중단해야 할 때

터미널에서 `Ctrl+C`를 한 번 누릅니다. 여러 프로세스가 종료되는 데 시간이 걸릴 수 있습니다.

중단된 실행의 `result_*` 폴더는 불완전한 결과입니다. 다음 원칙을 지킵니다.

1. 중단된 폴더 이름을 기록합니다.
2. 해당 폴더의 결과를 정상 완료 결과와 비교하지 않습니다.
3. 같은 명령을 다시 실행하면 새 시간의 결과 폴더가 생성됩니다.
4. 기존 결과 폴더를 덮어쓰지는 않습니다.

노트북 절전, Windows 업데이트 재시작, VS Code 종료가 발생하지 않도록 합니다.

## 11. 자주 발생하는 오류

### `ModuleNotFoundError`

원인: 가상환경이 활성화되지 않았거나 패키지가 없습니다.

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install pandas matplotlib tqdm openpyxl
```

### `running scripts is disabled`

현재 터미널에서 다음 명령을 실행한 뒤 다시 활성화합니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```

### `unable to open database file`

다음을 확인합니다.

```text
C:\FREE\gitTest\Database\stock_price(1day_total).db
```

그리고 터미널 현재 경로가 다음인지 확인합니다.

```text
C:\FREE\gitTest\BUJA_Strategy_v1
```

### `JSONDecodeError`

설정 파일의 쉼표, 대괄호 또는 따옴표가 잘못된 것입니다. 마지막 항목 뒤 쉼표가 없는지 먼저 확인합니다.

### 컴퓨터가 매우 느려짐

`overnight_test.json`은 현재 종목당 480조합입니다. 먼저 `smoke_test.json`을 사용하고, 필요하면 `strategies` 또는 `profit_loss_ratios` 항목 수를 줄입니다.

### Excel 파일을 열 수 없거나 결과가 비어 있음

백테스트가 아직 실행 중이거나 중단되었을 수 있습니다. 터미널에 `총 소요시간`이 표시된 뒤 결과를 엽니다.

## 12. 권장 운영 절차

1. 데이터베이스의 최신 날짜와 파일 존재 여부를 확인합니다.
2. `python Main.py smoke_test.json`으로 1개 조합을 실행합니다.
3. 결과 폴더와 Excel이 정상 생성됐는지 확인합니다.
4. `overnight_test.json`을 별도 이름으로 복사해 실험 목적을 기록합니다.
5. 한 번에 한 종류의 가설만 변경합니다.
6. `python Main.py overnight_test.json`을 실행합니다.
7. `result_list.txt`의 최신 구간과 결과 Excel을 확인합니다.
8. 수익합계뿐 아니라 매매횟수, 기대값, 연도별 결과를 비교합니다.
9. 우수 전략은 다른 신고가 기간과 손절 폭에서도 재검증합니다.
10. 최종 후보는 실전 적용 전 별도의 기간 또는 모의투자로 검증합니다.

### 실험 기록 예시

```text
실행일: 2026-08-10
설정 파일: overnight_test.json
목적: EMA 50/200 조합과 4R/99R 비교
결과 폴더: result_2026-08-10_22-30-00
후보 전략: singo_240_medo_50_200_[10, 4]
주의사항: 2024년 수익이 전체 결과에 미치는 영향 별도 확인
```

이 기록을 남겨야 과거에 어떤 설정으로 실행했는지 혼동하지 않습니다.
