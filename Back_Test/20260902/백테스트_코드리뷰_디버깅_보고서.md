### 1. 초기 손절가(loss_cut_price)가 0으로 설정됨 — 초기 손절 작동 안함

**위치:** `strategy/One_Day_Minervini_Mark_V1.py` (매수 시점)

**문제:**
- 매수 시 `loss_cut_n = 1`로 리셋하지만, `loss_cut_price`를 초기 손절가로 설정하지 않음
- `loss_cut_price`는 가격이 +10%(profit_loss_ratio[0]) 이상 상승한 이후에만 설정됨
- 즉, 매수 후 +10% 도달 전까지는 `loss_cut_price = 0`이므로 `close < loss_cut_price` 조건이 절대 발동하지 않음
- **매수 직후 -9%까지 하락해도 손절이 안 됨!**

**수정 방법:**
```python
# 매수 직후 아래 코드 추가 (buy_price 확정 후)
loss_cut_price = int(buy_price * (1 - profit_loss_ratio[0] / 100))
```

### 6. 부분 익절 후 loss_cut_price가 갱신되지 않음

**문제:**
- 50% 부분 익절 후 `Alread_Get_R = True`가 되지만, loss_cut_price는 이전 값 유지
- 큰 수익을 보고 부분 익절 했는데, 가격이 급락하면 이미 이전 단계의 loss_cut_price까지 내려가야 나머지가 손절됨
- 익절 시점의 가격으로 loss_cut_price를 올려주는 것이 합리적

**수정 제안:**
```python
if not Alread_Get_R and close >= buy_price * (1 + (profit_loss_ratio[0] * profit_loss_ratio[1]) / 100):
    # ... 기존 코드 ...
    Alread_Get_R = True
    # 부분 익절 시 loss_cut_price를 현재가 기준으로 갱신
    loss_cut_price = buy_price * (1 + profit_loss_ratio[0] * (profit_loss_ratio[1] - 1) / 100)
    continue
```

## 🟢 개선 제안

### 9. 최대 낙폭(MDD) 추적 추가

현재 수익률만 기록하고 있음. 최대 낙폭을 추적하면 전략의 리스크를 더 잘 파악 가능.

```python
# 전략 함수 내부에 추가
max_portfolio_value = initBuget
max_drawdown = 0

# 매 거래 종료 후:
current_value = buget + remaining_qty * close
if current_value > max_portfolio_value:
    max_portfolio_value = current_value
drawdown = (max_portfolio_value - current_value) / max_portfolio_value * 100
if drawdown > max_drawdown:
    max_drawdown = drawdown
```

### 10. 슬리피지 적용 시점 문제

**문제:**
- 매수: `buy_price = int(buy_price * (1 + util.SLIPPAGE_BUY / 100))` → 매수가에 0.5% 추가 (OK)
- 매도: `sell_price = int(sell_price * (1 - util.SLIPPAGE_SELL / 100))` → 매도가에서 0.5% 차감 (OK)
- 그러나 `profit = (sell_price - buy_price) / buy_price * 100`에서 sell_price는 슬리피지 적용된 값이지만,
  매도 조건 판단은 `close`(슬리피지 미적용)로 하고 있어 실제 매도 시점 결정이 약간 낙관적

### 11. ProcessPoolExecutor에서 Lock 사용 불가

**위치:** `Main.py`

**문제:**
```python
lock = Lock()  # threading.Lock은 프로세스 간 공유 불가

# process_table_strategy 안에서:
lock.acquire()  # 다른 프로세스에서는 이 lock에 접근 불가
```
- `ProcessPoolExecutor`는 별도 프로세스를 생성하므로 `threading.Lock`이 작동하지 않음
- 현재 `SAVE_LOG_FILE_CHART = False`이므로 실제 문제는 발생하지 않지만, 차트 저장 기능 활성화 시 레이스 컨디션 발생 가능

**수정 방법:** `multiprocessing.Lock`을 사용하거나, 차트 저장을 메인 프로세스에서 수행
